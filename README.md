# Workier — Putter Workspace

แอปบริหารงานส่วนตัวสำหรับคนที่ทำหลายโปรเจกต์พร้อมกัน ออกแบบตามลำดับการทำงานจริง:

> รับข้อมูล → จับประเด็น → กำหนดของที่จะส่ง → เลือกงานวันนี้ → ติดตาม → เตรียมอัปเดตหัวหน้า

ภาษาไทยทั้งแอป ใช้งานบนมือถือได้ครบทุกขั้นตอน ติดตั้งเป็น PWA ได้ และ **ไม่มีหน้า login**

---

## หน้าจอหลัก

| หน้า | ทำอะไร |
|---|---|
| `/` **วันนี้** | เลือกงานหลักไม่เกิน 3 ชิ้น · กรอกเวลาที่มีจริง · เตือนเมื่อเวลาประมาณการเกิน · AI เสนอลำดับพร้อมเหตุผล · แยกงานที่รอคนอื่น · ยกงานเมื่อวานที่ยังไม่เสร็จมาให้จัดใหม่ |
| `/inbox` **รับข้อมูล** | วางข้อความจากอีเมล/แชต/โน้ตประชุม → AI จับประเด็นและเสนอร่างงาน → แก้ไข เลือกรับบางงาน หรือตัดออก ก่อนยืนยัน |
| `/tasks` **ติดตาม & Timeline** | ดูทุกโปรเจกต์หรือเฉพาะโปรเจกต์ · เริ่ม → ร่าง → รีวิว → ส่ง · เลยกำหนด / ใกล้ถึงกำหนด / ควรเริ่มแล้ว / ไม่มีวันส่ง · ตรวจลำดับวันที่ · AI เสนอแผนย้อนจากวันส่ง |
| `/projects` **โปรเจกต์** | เพิ่ม/แก้ไข/เก็บเข้าคลังได้ไม่จำกัด · หน้ารวมของแต่ละโปรเจกต์ |
| `/brief` **เตรียมคุยและพรีเซน** | สรุป 5 ประเด็น · สรุปหนึ่งหน้า · บทพูด 2 นาที · โครงสไลด์ 3–5 หน้า · คำถามที่หัวหน้าอาจถาม — แก้ไข คัดลอก และบันทึกย้อนหลังได้ |
| `/settings` **ตั้งค่า** | กุญแจ API + ทดสอบการเชื่อมต่อ · รหัสพื้นที่ทำงาน · ข้อมูลตัวอย่าง |

## โครงสร้างเทคนิค

- **Next.js 15 (App Router) + TypeScript + Tailwind CSS** — deploy บน Vercel
- **Firebase Firestore** สำหรับเก็บข้อมูล + **Anonymous Auth** (ไม่มีหน้า login แต่ยังมีการตรวจสิทธิ์ระดับ Firestore rules)
- **Anthropic Claude API** เรียกผ่าน API route ฝั่งเซิร์ฟเวอร์เท่านั้น
- **PWA** — `manifest.webmanifest` + service worker (network-first สำหรับหน้าเว็บ, ไม่แคช `/api/*`)

```
src/
  app/                 หน้าเว็บ + API routes (/api/ai/*)
  components/          UI ที่ใช้ร่วมกัน (task card, task editor, app shell, …)
  lib/
    types.ts           โครงสร้างข้อมูลทั้งหมด
    store.tsx          React context: โหลด/บันทึก/ตรวจการแก้ไขชนกัน
    repo-firestore.ts  ที่เก็บข้อมูลหลัก (Firestore)
    repo-local.ts      ที่เก็บสำรองในเบราว์เซอร์ เมื่อยังไม่ตั้งค่า Firebase
    server/            โค้ดฝั่งเซิร์ฟเวอร์: กุญแจ API, การเรียกโมเดล, JSON schema
firestore.rules        กติกาการเข้าถึงข้อมูล
```

## ตัวแปรสภาพแวดล้อม

### AI (ฝั่งเซิร์ฟเวอร์เท่านั้น — ไม่เคยส่งมายังเบราว์เซอร์)

| ตัวแปร | จำเป็น | คำอธิบาย |
|---|---|---|
| `ANTHROPIC_API_KEY` | ไม่ | กุญแจ Anthropic ถ้าไม่ตั้ง แอปยังทำงานได้ทุกอย่าง ยกเว้นฟีเจอร์ AI ซึ่งจะแจ้งตรง ๆ ว่ายังไม่ได้ตั้งค่า และเพิ่มกุญแจได้ที่ `/settings` |
| `ANTHROPIC_MODEL` | ไม่ | ค่าเริ่มต้น `claude-opus-5` |
| `WORKIER_SECRET` | ไม่ | ถ้าตั้ง กุญแจที่กรอกผ่าน `/settings` จะถูกเข้ารหัส AES-256-GCM ก่อนเก็บลงคุกกี้ |

### Firebase (ค่าเหล่านี้เปิดเผยได้ตามการออกแบบ — ความปลอดภัยอยู่ที่ `firestore.rules`)

`NEXT_PUBLIC_FIREBASE_API_KEY`, `NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN`,
`NEXT_PUBLIC_FIREBASE_PROJECT_ID`, `NEXT_PUBLIC_FIREBASE_STORAGE_BUCKET`,
`NEXT_PUBLIC_FIREBASE_MESSAGING_SENDER_ID`, `NEXT_PUBLIC_FIREBASE_APP_ID`

**ถ้าเว้นว่างทั้งหมด** แอปจะเก็บข้อมูลไว้ในเบราว์เซอร์นั้นเครื่องเดียว และแสดงแถบเตือนไว้ตลอด — ไม่แอบอ้างว่าซิงก์

## ตั้งค่า Firebase

1. สร้างโปรเจกต์ที่ [console.firebase.google.com](https://console.firebase.google.com)
2. **Authentication → Sign-in method → เปิด "Anonymous"** (จำเป็น เพราะ rules ต้องการผู้ใช้ที่ผ่านการยืนยัน)
3. **Firestore Database → Create database** (production mode)
4. คัดลอกค่า config จาก Project settings → Your apps → Web app ไปใส่เป็น environment variables
5. Deploy rules:
   ```bash
   npx firebase deploy --only firestore:rules
   ```

### โมเดลการเข้าถึงข้อมูล (สำคัญ)

แอปนี้ไม่มีหน้า login ตามที่กำหนด แต่ **ไม่ได้เปิดข้อมูลให้ใครก็ได้**:

- ทุกอุปกรณ์ sign in แบบ anonymous ดังนั้น Firestore เห็น principal ที่ผ่านการยืนยันเสมอ
- ข้อมูลอยู่ใต้ `workspaces/{workspaceId}/…` โดย `workspaceId` เป็นรหัสสุ่ม 24 ตัวอักษรที่สร้างในเครื่อง
- อุปกรณ์ที่รู้รหัสจะบันทึกตัวเองไว้ในรายชื่อ `members` และเฉพาะสมาชิกเท่านั้นที่อ่าน/เขียนได้

**ข้อจำกัดที่ต้องรู้:** รหัสพื้นที่ทำงานทำหน้าที่เหมือนรหัสผ่าน ใครที่ได้รหัสไปจะเข้าถึงข้อมูลได้
ให้เก็บเป็นความลับ (ดูรหัสได้ที่ `/settings`) ถ้าต้องการความปลอดภัยสูงกว่านี้ ต้องเพิ่มการ login จริง

**ใช้ข้อมูลชุดเดียวกันบนอุปกรณ์อื่น:** คัดลอกรหัสจาก `/settings` ของเครื่องเดิม ไปวางในช่อง
"รหัสพื้นที่ทำงาน" ของเครื่องใหม่แล้วกด "สลับพื้นที่ทำงาน"

## Deploy บน Vercel

1. Import repository นี้เข้า Vercel (Next.js ตรวจจับอัตโนมัติ ไม่ต้องตั้งค่า build)
2. ใส่ environment variables ตามตารางด้านบนใน Project Settings → Environment Variables
3. Deploy

การอัปเดตแอปไม่กระทบข้อมูลเดิม เพราะงาน โน้ต และโปรเจกต์ทั้งหมดอยู่ใน Firestore ไม่ได้อยู่ในโค้ด

## หลักการทำงานของ AI ในแอปนี้

- **เรียกโมเดลจริง** ผ่าน Anthropic Messages API (structured output ด้วย JSON schema) ไม่มีการแยกบรรทัดหรือข้อความสำเร็จรูปมาแอบอ้างว่าเป็น AI
- **กุญแจอยู่ฝั่งเซิร์ฟเวอร์เท่านั้น** — ไม่อยู่ใน bundle ของเบราว์เซอร์ ไม่อยู่ใน log และไม่เคยถูกส่งกลับมา
  กุญแจที่กรอกผ่าน `/settings` เก็บในคุกกี้ `httpOnly` (สคริปต์ในหน้าเว็บอ่านไม่ได้) และเข้ารหัสถ้าตั้ง `WORKIER_SECRET`
- **ทดสอบการเชื่อมต่อจริงก่อนบันทึก** — ถ้ากุญแจใช้ไม่ได้ จะไม่บันทึกและไม่แสดงว่าเชื่อมต่อสำเร็จ
- **ผลลัพธ์ AI เป็นร่างเสมอ** ติดป้ายชัดเจน และไม่เปลี่ยนข้อมูลจริงจนกว่าผู้ใช้จะยืนยัน
- **ห้ามแต่งข้อมูล** — prompt บังคับให้ใส่ `null` เมื่อไม่มีวันที่ และเว้นว่างเมื่อไม่ทราบผู้รับผิดชอบ
- **เวลาประมาณการจาก AI ติดป้าย "เวลาประมาณจาก AI"** จนกว่าผู้ใช้จะเปิดแก้ไขและบันทึก
- **ข้อความผิดพลาดบอกสาเหตุที่แก้ได้จริง**: กุญแจไม่ถูกต้อง · เครดิตไม่พอ · เรียกถี่เกินไป · บริการไม่ตอบ · เชื่อมต่อไม่ได้
- **เมื่อ AI ล้มเหลว ข้อความที่กรอกไว้ไม่หาย** และยังบันทึกหรือจัดงานเองได้ตามปกติ

## การบันทึกข้อมูลและการแก้ไขชนกัน

ทุกเรคอร์ดมีเลข `rev` การบันทึกจะส่ง `rev` ที่หน้าจอเห็นล่าสุดไปด้วย ถ้าฐานข้อมูลมี `rev` ใหม่กว่า
(แปลว่ามีหน้าต่างหรืออุปกรณ์อื่นบันทึกไปก่อน) ระบบจะ **ไม่เขียนทับ** แต่จะแจ้งเตือนว่าข้อมูลถูกแก้ไขจากที่อื่น
ให้รีเฟรชแล้วแก้อีกครั้ง สถานะ "กำลังบันทึก / บันทึกแล้ว / บันทึกไม่สำเร็จ" แสดงอยู่บนหัวจอเสมอ

## ข้อมูลตัวอย่าง

พื้นที่ทำงานใหม่จะมีข้อมูลตัวอย่าง 3 โปรเจกต์และ 4 งาน ทุกชิ้นติดป้าย **ตัวอย่าง**
ไม่ถือเป็นสถานะงานจริง และลบทั้งหมดได้ในคลิกเดียวจากหน้า `/projects` หรือ `/settings`
